What the audit actually found

Summary

Most of what a from-scratch audit would flag here had already been fixed by three earlier passes: three table paradigms collapsed into one, per-feature headers replaced by a shared module header, page-replacing action errors converted to snackbars. Adoption is real and measurable — 83 collapsible sections carrying a registered sectionId, one search widget, all 26 error states carrying a retry, and only three hardcoded colours in 108k lines.

That left two things worth an engineer's day: a single layout bug that had been written off as an accepted test failure, and one module that never received any of those passes.

The one P0

Severity · Broken
التشغيل › إنشاء رحلة — trip_creation_wizard.dart · _InteractiveTimeTile

Trip wizard overflowed at enlarged text Fixed

The date and time tiles were pinned to width: 220 with no Flexible on the label row. At 1.3× text scale the Arabic label overflowed by 19px; at 1.6×, by 62px — a striped overflow banner across the console's highest-stakes form.

The design system already documented this trap for aligned control lanes. It recurred one level deeper, on a tile inside a Wrap. The fix is a ConstrainedBox(minWidth:), MainAxisSize.min, and a Flexible label — the tiles can grow, and growing costs only a reflow.

It had been carried in the known-issues file as a pre-existing failure. Enlarged text is the most-used accessibility setting there is.

The drifted module

Severity · Major

مركز الشكاوى والدعم — the support desk — missed every consistency pass. Four separate P1s, all in one module, all fixed together.

English text on an Arabic-only console Fixed

Status and priority badges printed Submitted, Under Review, Urgent. The SLA column read BREACHED and 2h 30m left. Six cubit snackbars were English. The support desk — staffed by the least technical operators — was the one module in a foreign language.

Safe to translate: the wire value was always .name, so nothing about persistence changed.

Filters existed but nothing could reach them Fixed

setFilterStatus and setFilterPriority existed and the queue honoured them — but no widget on screen ever called them. An agent could not ask "show me the urgent open tickets", which is the queue's primary question.

This is the inverse of the guideline the console already enforces: a control that cannot reach the query is not a control. Here, a query that no control could reach.

Unpaginated, unsorted, header scrolling away Fixed

A raw Material DataTable inside nested scroll views — the console's last one. Every filtered ticket built at once, column headers scrolling out of view, no sort on SLA or date. A support queue's entire job is knowing what breaches next.

Migrated to the shared OpsDataTable: 12 rows per page, sticky header, five sortable columns, defaulting to the SLA clock soonest-first.

Empty states that said nothing Fixed

A bare "لا توجد تذاكر." answers none of the three questions an empty state owes the reader. Now two distinct states: never-had-any explains where tickets come from; filtered-to-nothing offers the way back out.

Still open

Honest list
Highest daily cost

Filters reset on navigation

The shell rebuilds each module on every route switch. Fold state already survives in a process-wide store; filter state is the obvious next tenant. Filter → open a booking → come back → start over.

Cheapest next P0

Pump every module at 1.6×

The one P0 here was found by a text-scale test that existed for exactly one widget. Most modules are only pumped at 1.0× — unproven, not proven-good.

Product decision

الرئيسية vs نظرة تنفيذية

Home's four KPIs are a subset of the executive tab's eleven. Sharpen to what must I do now versus how are we doing — a product call, not a cleanup.

Duplication

Payment verification vs bookings

2.0k lines against 5.8k, same table, same three RPCs. Fold into a saved queue preset; keep the route as a deep link.

Partial adoption

Empty-state sweep

Seven of 25 modules use the dashboard empty state; the rest still use the page-sized, emoji-led one built for the mobile apps.

Never done

Screen-reader pass

Sort headers, icon-only buttons and status badges convey meaning by colour and glyph alone.

Found, deliberately not changed

Backend dependencies

Each presents as a UX problem and none is fixable in Flutter. Listed so nobody re-discovers them as UI bugs.

Unbounded list queries Backend

الرئيسية fires nine uncapped queries per visit, نظرة تنفيذية twelve, re-run on every return. Presents as "the dashboard is slow", worsening linearly with office age. Needs server-side aggregates and paging.

Reports cannot be date-bounded Backend

The driver, vehicle and complaint views are lifetime roll-ups with no date column. The UI now says so instead of drawing an inert date picker — removing the lie was the right frontend move; closing the gap is a migration.

Four report KPIs do not exist Backend

Driver rating, working hours, fuel consumption and complaint resolution time were read by column name from views that never had them. Removed rather than faked.
